## 1. 功能概述

### 1.1 功能定位

**配置查询**是基于现有模板管理的增强功能，允许用户创建带参数的 SQL 查询模板，通过可视化的参数表单或 JSON 输入快速执行查询，降低 SQL 编写门槛。

### 1.2 核心价值

| 用户角色 | 价值 |
|---------|------|
| 管理员 | 创建标准化查询模板，公开给团队使用，减少重复沟通 |
| 普通用户 | 无需编写 SQL，通过填写参数即可查询数据 |
| 数据分析师 | 将常用查询参数化，提高工作效率 |
| 技术用户 | 通过 JSON 快速批量设置参数，支持脚本化调用 |

### 1.3 核心特性

- **可收缩面板布局**：SQL预览和参数配置可切换收缩，确保每个区域都能完整展示
- **双输入模式**：支持表单输入和 JSON 输入两种方式
- **双向同步**：表单和 JSON 实时双向同步
- **参数预设**：保存常用参数组合，快速复用
- **权限管理**：管理员可公开，普通用户管理自己的配置

### 1.4 与现有功能关系


| 编辑自己的配置查询 | ✅ | ✅ |
| 删除自己的配置查询 | ✅ | ✅ |
| 编辑他人的配置查询 | ✅ | ❌ |

### 2.2 可见性规则

```
用户可见的配置查询 = 自己创建的 + 管理员公开的
```

### 2.3 数据权限

配置查询执行时，遵循现有的平台/连接权限：
- 用户只能选择有权限的平台和连接
- 配置查询可以绑定默认连接，但用户必须有该连接权限才能执行

## 3. 数据模型

### 3.1 数据库表设计

#### ConfigQueries（配置查询主表）

```sql
CREATE TABLE ConfigQueries (
    Id              INT PRIMARY KEY AUTO_INCREMENT,
    Name            VARCHAR(100) NOT NULL,           -- 配置查询名称
    Description     VARCHAR(500),                    -- 描述说明
    SqlContent      TEXT NOT NULL,                   -- SQL 模板（含参数占位符）
    ConnectionId    INT,                             -- 默认数据库连接（可选）
    IsPublic        BOOLEAN DEFAULT FALSE,           -- 是否公开
    CreatedBy       INT NOT NULL,                    -- 创建者 ID
    SortOrder       INT DEFAULT 0,                   -- 排序
    IsActive        BOOLEAN DEFAULT TRUE,            -- 是否启用
    CreatedAt       DATETIME DEFAULT CURRENT_TIMESTAMP,
    UpdatedAt       DATETIME DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,

    FOREIGN KEY (ConnectionId) REFERENCES DatabaseConnections(Id),
    FOREIGN KEY (CreatedBy) REFERENCES Users(Id),
    INDEX idx_created_by (CreatedBy),
    INDEX idx_is_public (IsPublic)
);
```

#### ConfigQueryParameters（参数配置表）

```sql
CREATE TABLE ConfigQueryParameters (
    Id              INT PRIMARY KEY AUTO_INCREMENT,
    ConfigQueryId   INT NOT NULL,                    -- 所属配置查询
    ParamName       VARCHAR(50) NOT NULL,            -- 参数名（@paramName 中的 paramName）
    ParamLabel      VARCHAR(100) NOT NULL,           -- 参数显示标签
    ParamType       VARCHAR(20) NOT NULL,            -- 参数类型
    IsRequired      BOOLEAN DEFAULT TRUE,            -- 是否必填
    DefaultValue    VARCHAR(500),                    -- 默认值
    Placeholder     VARCHAR(200),                    -- 输入框占位提示
    OptionsConfig   TEXT,                            -- 下拉选项配置（JSON）
    ValidationRule  VARCHAR(200),                    -- 校验规则（正则表达式）
    ExtraConfig     TEXT,                            -- 扩展配置（JSON，如数字范围、日期格式等）
    SortOrder       INT DEFAULT 0,                   -- 参数排序

    FOREIGN KEY (ConfigQueryId) REFERENCES ConfigQueries(Id) ON DELETE CASCADE,
    UNIQUE KEY uk_query_param (ConfigQueryId, ParamName)
);
```

#### ConfigQueryParamPresets（参数预设表 - 新增）

```sql
CREATE TABLE ConfigQueryParamPresets (
    Id              INT PRIMARY KEY AUTO_INCREMENT,
    ConfigQueryId   INT NOT NULL,                    -- 所属配置查询
    Name            VARCHAR(100) NOT NULL,           -- 预设名称
    ParamValues     TEXT NOT NULL,                   -- 参数值 JSON
    CreatedBy       INT NOT NULL,                    -- 创建者
    IsDefault       BOOLEAN DEFAULT FALSE,           -- 是否为默认预设
    CreatedAt       DATETIME DEFAULT CURRENT_TIMESTAMP,

    FOREIGN KEY (ConfigQueryId) REFERENCES ConfigQueries(Id) ON DELETE CASCADE,
    FOREIGN KEY (CreatedBy) REFERENCES Users(Id),
    INDEX idx_config_query (ConfigQueryId)
);
```

### 3.2 参数类型枚举

| ParamType | 说明 | 组件 | JSON 值类型 |
|-----------|------|------|-------------|
| `text` | 文本输入 | el-input | `string` |
| `number` | 数字输入 | el-input-number | `number` |
| `date` | 日期选择 | el-date-picker (date) | `string` (yyyy-MM-dd) |
| `daterange` | 日期范围 | el-date-picker (daterange) | `[string, string]` |
| `select` | 下拉单选 | el-select | `string` |
| `multiselect` | 下拉多选 | el-select (multiple) | `string[]` |

### 3.3 下拉选项配置格式 (OptionsConfig)

#### 固定选项模式

```json
{
  "mode": "static",
  "options": [
    { "label": "待支付", "value": "0" },
    { "label": "已支付", "value": "1" },
    { "label": "已取消", "value": "2" }
  ]
}
```

#### 动态 SQL 查询模式

```json
{
  "mode": "dynamic",
  "sql": "SELECT id as value, name as label FROM categories WHERE is_active = 1",
  "connectionId": 1,
  "refreshOnOpen": true
}
```

### 3.4 扩展配置格式 (ExtraConfig)

#### 数字类型扩展配置

```json
{
  "min": 0,
  "max": 999999999,
  "precision": 2,
  "step": 1
}
```

#### 日期类型扩展配置

```json
{
  "format": "yyyy-MM-dd",
  "defaultType": "today",        // none | today | yesterday | custom
  "customDefault": "2024-01-01"
}
```

#### 日期范围扩展配置

```json
{
  "format": "yyyy-MM-dd",
  "defaultType": "last7days",    // none | last7days | last30days | thisMonth | custom
  "startParamName": "startDate",
  "endParamName": "endDate"
}
```

## 4. 参数值输入模式

### 4.1 双模式设计

支持两种参数输入方式，用户可自由切换或同时使用：

| 模式 | 说明 | 适用场景 |
|------|------|---------|
| **表单模式** | 可视化表单逐个填写参数 | 普通用户、首次使用、参数较少时 |
| **JSON 模式** | 直接编辑 JSON 格式参数值 | 技术用户、批量设置、复用历史参数 |
| **双视图模式** | 表单和 JSON 同时显示，双向同步 | 需要同时查看和编辑两种格式 |

### 4.2 参数值 JSON 格式

根据参数配置定义，参数值的 JSON 格式如下：

```json
{
  "startDate": "2024-01-01",
  "endDate": "2024-01-31",
  "status": "1",
  "minAmount": 100,
  "keyword": "测试",
  "tags": ["tag1", "tag2", "tag3"]
}
```

#### 各参数类型的 JSON 值格式

| 参数类型 | JSON 值格式 | 示例 |
|---------|------------|------|
| `text` | `string` | `"搜索关键词"` |
| `number` | `number` | `100` 或 `99.99` |
| `date` | `string` (日期格式) | `"2024-01-15"` |
| `daterange` | `[string, string]` | `["2024-01-01", "2024-01-31"]` |
| `select` | `string` | `"1"` |
| `multiselect` | `string[]` | `["1", "2", "3"]` |

### 4.3 JSON 与表单双向同步规则

```
┌─────────────────┐              ┌─────────────────┐
│                 │   同步 →     │                 │
│   表单输入       │◄─────────────│   JSON 编辑器   │
│                 │   ← 同步     │                 │
└─────────────────┘              └─────────────────┘
        │                                │
        │         实时校验               │
        ▼                                ▼
┌─────────────────────────────────────────────────┐
│                 参数值状态                       │
│  paramValues: { startDate: "...", ... }         │
└─────────────────────────────────────────────────┘
```

**同步规则：**
1. 表单修改 → 自动更新 JSON 显示
2. JSON 修改 → 解析成功后自动更新表单
3. JSON 格式错误 → 显示错误提示，不更新表单
4. JSON 值类型错误 → 显示警告，尝试类型转换

### 4.4 参数预设功能

用户可以保存常用的参数组合为预设，方便快速复用：

```json
// 预设示例
{
  "id": 1,
  "name": "本月已完成订单",
  "configQueryId": 1,
  "paramValues": {
    "startDate": "2024-01-01",
    "endDate": "2024-01-31",
    "status": "3",
    "minAmount": 0
  }
}
```

## 7. 参数替换规则

### 7.1 基本替换

参数使用 `@paramName` 格式，执行时进行安全替换：

```sql
-- 模板
SELECT * FROM orders WHERE status = @status

-- 参数 JSON: { "status": "1" }
-- 替换后
SELECT * FROM orders WHERE status = '1'
```

### 7.2 类型处理

| 参数类型 | JSON 值示例 | 替换结果 |
|---------|------------|---------|
| text | `"abc"` | `'abc'` |
| number | `100` | `100` |
| date | `"2024-01-01"` | `'2024-01-01'` |
| daterange | `["2024-01-01", "2024-01-31"]` | 替换为两个独立参数 |
| select | `"1"` | `'1'` |
| multiselect | `["1", "2", "3"]` | `'1','2','3'` |

### 7.3 空值处理

```sql
-- 模板（支持空值的写法）
SELECT * FROM orders
WHERE (@status = '' OR status = @status)

-- 参数 JSON: { "status": "" }
-- 替换后
SELECT * FROM orders
WHERE ('' = '' OR status = '')
-- 条件始终为真，不过滤
```

### 7.4 多选值处理

```sql
-- 模板
SELECT * FROM orders WHERE status IN (@statusList)

-- 参数 JSON: { "statusList": ["1", "2"] }
-- 替换后
SELECT * FROM orders WHERE status IN ('1','2')
```

### 7.5 SQL 注入防护

- 所有参数值进行转义处理
- 字符串类型自动添加引号
- 禁止参数值中包含注释符号
- 后端二次校验 SQL 安全性

### 8.2 状态管理

```typescript
// stores/configQuery.ts
interface ConfigQueryState {
  // 列表
  list: ConfigQuery[];
  loading: boolean;

  // 当前选中
  currentId: number | null;
  currentQuery: ConfigQuery | null;

  // 输入模式
  inputMode: 'form' | 'json' | 'dual';

  // 参数值（表单和 JSON 共享此状态）
  paramValues: Record<string, any>;

  // JSON 编辑器内容（用于语法错误时保留用户输入）
  jsonEditorContent: string;
  jsonParseError: string | null;

  // 参数预设
  presets: ParamPreset[];
  currentPresetId: number | null;

  // 执行结果
  result: QueryResult | null;
  executing: boolean;
}

interface ConfigQuery {
  id: number;
  name: string;
  description: string;
  sqlContent: string;
  connectionId: number | null;
  isPublic: boolean;
  createdBy: number;
  createdByName: string;
  isOwner: boolean;
  canEdit: boolean;
  parameters: ConfigQueryParameter[];
}

interface ConfigQueryParameter {
  id: number;
  paramName: string;
  paramLabel: string;
  paramType: 'text' | 'number' | 'date' | 'daterange' | 'select' | 'multiselect';
  isRequired: boolean;
  defaultValue: string;
  placeholder: string;
  optionsConfig: OptionsConfig | null;
  extraConfig: ExtraConfig | null;
  validationRule: string;
  sortOrder: number;
}

interface ParamPreset {
  id: number;
  name: string;
  paramValues: Record<string, any>;
  isDefault: boolean;
  createdAt: string;
}

// 双向同步逻辑
const syncFormToJson = () => {
  jsonEditorContent.value = JSON.stringify(paramValues.value, null, 2);
  jsonParseError.value = null;
};

const syncJsonToForm = () => {
  try {
    const parsed = JSON.parse(jsonEditorContent.value);
    paramValues.value = parsed;
    jsonParseError.value = null;
  } catch (e) {
    jsonParseError.value = 'JSON 格式错误: ' + e.message;
  }
};
```

### 8.3 JSON 编辑器配置

使用 Monaco Editor 提供 JSON 编辑能力：

```typescript
// JSON 编辑器配置
const jsonEditorOptions = {
  language: 'json',
  theme: 'vs-dark',
  automaticLayout: true,
  minimap: { enabled: false },
  lineNumbers: 'on',
  scrollBeyondLastLine: false,
  formatOnPaste: true,
  formatOnType: true,
  tabSize: 2
};

// JSON Schema 用于智能提示
const generateJsonSchema = (parameters: ConfigQueryParameter[]) => {
  const properties: Record<string, any> = {};

  parameters.forEach(param => {
    switch (param.paramType) {
      case 'text':
      case 'date':
      case 'select':
        properties[param.paramName] = { type: 'string' };
        break;
      case 'number':
        properties[param.paramName] = { type: 'number' };
        break;
      case 'daterange':
        properties[param.paramName] = {
          type: 'array',
          items: { type: 'string' },
          minItems: 2,
          maxItems: 2
        };
        break;
      case 'multiselect':
        properties[param.paramName] = {
          type: 'array',
          items: { type: 'string' }
        };
        break;
    }
  });

  return {
    type: 'object',
    properties,
    required: parameters.filter(p => p.isRequired).map(p => p.paramName)
  };
};
```
