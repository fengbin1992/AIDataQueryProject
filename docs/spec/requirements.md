# AIDataQuery 需求文档

## 引言

AIDataQuery 是一套企业级数据查询中心系统，为企业提供统一的多数据源 SQL 查询平台。本文档详细定义了系统的功能需求和非功能需求。

## 产品愿景对齐

本需求文档支持产品愿景中的以下目标：
- 统一入口：通过平台编码统一管理多数据源
- 安全可控：实现完整的用户认证和权限管理
- 高效便捷：提供 SQL 模板和智能提示功能
- 美观易用：现代化 UI 设计，支持主题切换

## 功能需求

### REQ-001 用户认证

**用户故事：** 作为用户，我希望通过账号密码登录系统，以便安全地访问数据查询功能。

#### 验收标准

1. WHEN 用户访问系统首页 THEN 系统 SHALL 显示登录页面
2. WHEN 用户输入正确的用户名和密码并点击登录 THEN 系统 SHALL 生成 JWT Token 并跳转到主页面
3. WHEN 用户输入错误的用户名或密码 THEN 系统 SHALL 显示错误提示信息
4. IF Token 过期或无效 THEN 系统 SHALL 自动跳转到登录页面
5. WHEN 用户点击退出登录 THEN 系统 SHALL 清除 Token 并返回登录页面

#### 详细说明

- JWT Token 有效期为 8 小时
- 密码使用 BCrypt 加密存储
- 支持记住登录状态（可选，30 天有效）

### REQ-002 用户管理

**用户故事：** 作为管理员，我希望管理系统用户，以便控制谁可以访问系统。

#### 验收标准

1. WHEN 管理员进入用户管理页面 THEN 系统 SHALL 显示用户列表（分页）
2. WHEN 管理员点击"新增用户" THEN 系统 SHALL 显示用户创建表单
3. WHEN 管理员填写完整信息并提交 THEN 系统 SHALL 创建新用户并显示成功提示
4. WHEN 管理员编辑用户信息并保存 THEN 系统 SHALL 更新用户信息
5. WHEN 管理员禁用某用户 THEN 该用户 SHALL 无法登录系统
6. IF 用户不是管理员 THEN 系统 SHALL 隐藏用户管理菜单

#### 用户属性

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| 用户名 | string | 是 | 唯一标识，3-20 字符 |
| 密码 | string | 是 | 最少 6 位 |
| 昵称 | string | 是 | 显示名称 |
| 角色 | enum | 是 | Admin/User |
| 状态 | enum | 是 | Active/Disabled |
| 邮箱 | string | 否 | 用于通知 |

### REQ-003 权限管理

**用户故事：** 作为管理员，我希望为用户分配平台访问权限，以便控制数据访问范围。

#### 验收标准

1. WHEN 管理员配置用户权限 THEN 系统 SHALL 显示可选的平台编码列表
2. WHEN 管理员为用户勾选平台 THEN 该用户 SHALL 只能查询已授权平台的数据
3. IF 用户未被授权访问某平台 THEN 该平台 SHALL 不在用户的平台选择列表中显示
4. WHEN 管理员为用户设置"全部平台"权限 THEN 用户 SHALL 可以访问所有平台

#### 权限模型

```
用户 (1) -----> (N) 用户平台权限 (N) <----- (1) 平台
```

### REQ-004 平台与数据库连接管理

**用户故事：** 作为管理员，我希望配置平台与数据库的对应关系，以便支持多数据源查询。

#### 验收标准

1. WHEN 管理员进入数据库配置页面 THEN 系统 SHALL 显示已配置的连接列表
2. WHEN 管理员新增数据库连接 THEN 系统 SHALL 使用 AES-256 加密连接字符串后存储到数据库
3. WHEN 管理员测试连接 THEN 系统 SHALL 验证连接有效性并显示结果
4. WHEN 管理员编辑连接 THEN 系统 SHALL 更新连接信息（重新加密）
5. WHEN 管理员删除连接 THEN 系统 SHALL 标记删除（软删除）

#### 连接字符串存储

- **存储位置**：SQLite 配置库的 `DatabaseConnections` 表
- **加密方式**：AES-256 加密存储
- **配置方式**：管理员通过管理界面配置，无需修改配置文件

#### 预置平台（需管理员配置连接）

| 平台编码 | 平台名称 | 说明 |
|----------|----------|------|
| ERP_HYYX_GXXQ | 【正式】ERP系统-好药优选-高新西区 | 需配置 ERP、ERP_CX、WMS、WMS_Mid 连接 |
| ERP_YYY_GXXQ | 【正式】ERP系统-药约约-高新西区 | 需配置 ERP、ERP_CX 连接 |
| ERP_YYY_CZ | 【正式】ERP系统-药约约-崇州 | 需配置 ERP、ERP_CX 连接 |
| ERP_YYY_TJ | 【正式】ERP系统-药约約-天津 | 需配置 ERP、ERP_CX 连接 |

### REQ-005 SQL 查询执行

**用户故事：** 作为用户，我希望执行 SQL 查询并查看结果，以便获取所需数据。

#### 验收标准

1. WHEN 用户选择平台和数据库 THEN 系统 SHALL 连接到对应的数据库
2. WHEN 用户输入 SQL 并点击执行 THEN 系统 SHALL 执行查询并显示结果
3. IF SQL 语句不是 SELECT 语句 THEN 系统 SHALL 拒绝执行并提示错误
4. IF 查询执行超时 THEN 系统 SHALL 终止查询并显示超时提示
5. WHEN 查询返回结果 THEN 系统 SHALL 以表格形式展示数据（分页）
6. WHEN 用户执行查询 THEN 系统 SHALL 记录查询历史

#### SQL 安全限制

- 仅允许 SELECT 语句
- 禁止 INSERT、UPDATE、DELETE、DROP、TRUNCATE 等语句
- 禁止存储过程调用（EXEC、EXECUTE）
- 查询超时限制：30 秒
- 单次查询返回行数限制：10000 行

---

### REQ-006 SQL 智能提示

**用户故事：** 作为用户，我希望在编写 SQL 时获得智能提示，以便提高查询效率。

#### 验收标准

1. WHEN 用户输入 SQL 关键字 THEN 编辑器 SHALL 显示关键字补全建议
2. WHEN 用户输入表名前缀 THEN 编辑器 SHALL 显示匹配的表名列表
3. WHEN 用户输入 "." 在表名后 THEN 编辑器 SHALL 显示该表的字段列表
4. WHEN 用户按 Tab 或 Enter THEN 编辑器 SHALL 插入选中的补全项

#### 提示内容

- SQL 关键字：SELECT、FROM、WHERE、JOIN、ORDER BY 等
- 表名：基于选中数据库的表列表
- 字段名：基于选中表的字段列表
- 函数：常用 SQL 函数

### REQ-007 查询模板（标签）管理

**用户故事：** 作为用户，我希望保存常用的 SQL 为模板，以便快速复用。

#### 验收标准

1. WHEN 用户点击"保存为模板" THEN 系统 SHALL 显示模板保存对话框
2. WHEN 用户选择模块和输入名称后保存 THEN 系统 SHALL 保存模板
3. WHEN 用户浏览模板列表 THEN 系统 SHALL 按模块分组显示模板
4. WHEN 用户点击模板 THEN 系统 SHALL 将模板 SQL 填入编辑器
5. WHEN 用户展开/折叠模块 THEN 系统 SHALL 显示/隐藏该模块下的模板

#### 预置模块结构

```
├── 客户模块
│   ├── KEY查询
│   ├── 基础查询
│   ├── 区域查询
│   ├── 发票查询
│   ├── 发货查询
│   ├── 经营范围查询
│   └── 证照查询
├── 商品模块
├── 订单模块
├── 库存模块
└── 自定义模块
```

#### 模板属性

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| 模板名称 | string | 是 | 显示名称 |
| SQL 内容 | text | 是 | SQL 语句 |
| 所属模块 | string | 是 | 分类模块 |
| 描述 | string | 否 | 说明文字 |
| 创建人 | string | 是 | 创建用户 |
| 是否公开 | bool | 是 | 是否对所有用户可见 |

### REQ-008 查询历史

**用户故事：** 作为用户，我希望查看我的查询历史，以便回顾和复用之前的查询。

#### 验收标准

1. WHEN 用户执行查询 THEN 系统 SHALL 记录查询历史
2. WHEN 用户打开查询历史 THEN 系统 SHALL 显示最近的查询记录（分页）
3. WHEN 管理员查看查询历史 THEN 系统 SHALL 可以查看所有用户的记录
4. IF 用户是普通用户 THEN 只能看到自己的查询记录
5. WHEN 用户点击历史记录 THEN 系统 SHALL 将 SQL 填入编辑器

#### 历史记录属性

| 字段 | 类型 | 说明 |
|------|------|------|
| SQL 内容 | text | 执行的 SQL |
| 执行时间 | datetime | 执行时间戳 |
| 执行用户 | string | 执行者用户名 |
| 平台编码 | string | 查询的平台 |
| 数据库名 | string | 查询的数据库 |
| 执行耗时 | int | 毫秒 |
| 返回行数 | int | 结果行数 |
| 执行状态 | enum | Success/Failed |
| 错误信息 | string | 失败时的错误 |

### REQ-009 主题切换

**用户故事：** 作为用户，我希望切换页面主题，以便根据个人偏好和环境调整界面。

#### 验收标准

1. WHEN 用户点击主题切换按钮 THEN 系统 SHALL 切换浅色/深色主题
2. WHEN 主题切换 THEN 系统 SHALL 即时更新所有页面元素颜色
3. WHEN 用户登录 THEN 系统 SHALL 应用用户上次选择的主题
4. IF 未设置主题偏好 THEN 系统 SHALL 使用系统默认主题（跟随系统）

#### 主题选项

- **浅色主题（Light）**：白色背景，深色文字
- **深色主题（Dark）**：深色背景，浅色文字
- **跟随系统（Auto）**：根据操作系统设置自动切换

---

### REQ-010 数据导出

**用户故事：** 作为用户，我希望导出查询结果，以便在其他工具中分析数据。

#### 验收标准

1. WHEN 用户点击"导出" THEN 系统 SHALL 显示导出格式选项
2. WHEN 用户选择 CSV 格式 THEN 系统 SHALL 生成 CSV 文件并下载
3. WHEN 用户选择 Excel 格式 THEN 系统 SHALL 生成 XLSX 文件并下载
4. IF 数据量超过 50000 行 THEN 系统 SHALL 提示用户缩小查询范围

## 非功能需求

### NFR-001 代码架构与模块化

- **单一职责原则**：每个文件应有单一、明确的用途
- **模块化设计**：组件、工具和服务应隔离且可复用
- **依赖管理**：最小化模块间的相互依赖
- **清晰接口**：组件和层之间定义清晰的契约

### NFR-002 性能要求

| 指标 | 要求 |
|------|------|
| 页面首次加载 | < 3 秒 |
| 常规 SQL 查询响应 | < 5 秒 |
| 复杂 SQL 查询响应 | < 30 秒 |
| 并发用户支持 | ≥ 50 用户 |
| API 响应时间 | < 500 毫秒（非查询接口） |

### NFR-003 安全要求

- 所有密码使用 BCrypt 加密存储
- 数据库连接密码使用 AES 加密存储
- 所有 API 接口需要 JWT 认证
- 实现 SQL 注入防护（只允许 SELECT）
- 实现 XSS 防护
- 敏感操作记录审计日志

### NFR-004 可靠性要求

- 系统可用性 ≥ 99.5%
- 数据库连接失败自动重试（3 次）
- 查询超时自动终止
- 错误信息友好展示，不暴露系统细节

### NFR-005 可用性要求

- 响应式布局，支持 1920x1080 及以上分辨率
- 主要操作 3 次点击内完成
- 提供操作反馈（加载状态、成功/失败提示）
- 支持键盘快捷键（Ctrl+Enter 执行查询）

### NFR-006 可维护性要求

- 代码注释覆盖率 ≥ 30%
- API 文档自动生成（Swagger）
- 日志分级记录（Debug/Info/Warning/Error）
- 配置项支持外部化

## 约束条件

1. **技术栈约束**
   - 后端必须使用 .NET 8 + Entity Framework Core
   - 前端必须使用 Vue 3
   - 系统配置数据使用 SQLite 存储

2. **安全约束**
   - 系统仅支持 SELECT 查询
   - 禁止任何数据修改操作

3. **部署约束**
   - 仅支持内网部署
   - 单实例部署（不考虑集群）

## 术语表

| 术语 | 定义 |
|------|------|
| 平台编码 | 标识一个业务平台的唯一编码，如 ERP_YYY_GXXQ |
| 数据库连接 | 一个具体的数据库实例连接配置 |
| 查询模板 | 预保存的 SQL 语句，可快速复用 |
| 模块 | 查询模板的分类，如"客户模块" |
| JWT | JSON Web Token，用于用户认证的令牌 |
